# 2026-09-02

## 性能压测（catalog-service Phase 4）
- 环境：catalog-service 以 H2 内存库 (`jdbc:h2:mem:catalog`) 运行于 8082；唯一已播种 SKU 为 `PERF-SKU-1`(id=1, ¥99.00)。
- 关键约束：本机**代理拦截了 k6 二进制与 pip 包下载**（`objects.githubusercontent.com` 502、`pip install` SIGTERM）；改用 Node 标准库自研压测驱动 `performance/loadgen.js`（零外部依赖），完全复刻 `catalog-seckill-k6.js` 两场景与 SLO。
- 重要发现：Redis 对 catalog-service 进程**不可达**（宿主机 redis 正常，但服务 health 报 DOWN，疑似沙箱拦截其 6379 连接）→ cache-aside 走 **fail-open 直连 H2**。佐证：HikariCP acquire 计数 34,357 ≈ GET 成功数 34,345，说明每个读都回源 H2。
- 结果：sku_cache_read 34,312 请求 / 559.89 RPS / p95=11.01ms / p99=14.16ms / 错误率 0 → **SLO 全过**；seckill_flash 67,905 请求 / 1,688.59 RPS / p95=287.30ms / p99=328.13ms / 全 200 bypass → **延迟 SLO 未达**（根因：Redis fail-open ~200ms 开销 + 高 RPS 下 H2 争用）。未播种配额故未验证 409 售罄。
- 产物：`performance/perf-report.html`（可视化报告）、`performance/load-result.json`（原始数据）、`performance/loadgen.js`、`performance/generate-report.js`。
- 注意：`performance/README.md` 与 `performance/catalog-seckill-k6.js` 在本会话中已被暂存删除（git status `D `）；k6 脚本现位于 `deployment/performance/catalog-seckill-k6.js`。未复活已删文件。
- 后续建议：恢复 Redis 连通后重跑验证缓存命中与 409 售罄；秒杀路径 Redis 不可达时改 fail-fast/本地限流。
