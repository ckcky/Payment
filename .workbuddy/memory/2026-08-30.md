## Phase 9 / 009-risk-security 实现（提交 6432209）

- 范围：渠道回调 HMAC 验签 + 防重放、`/internal/**` 内部鉴权、密钥 env 注入 + 脱敏、最小风控（只观测不拦截）。ADR-0024~0028 合并在 `docs/adr/0009-risk-security-decisions.md`（用户要求：四五个 ADR 放一个文档，不要一个 ADR 一个文档）。
- **关键坑 1（务必记住）**：Spring Boot 的 MockMvc **只收集 `FilterRegistrationBean`**；把 `OncePerRequestFilter` 仅标 `@Component` 会导致集成测试绕过过滤器 → 「测试全绿、生产裸奔」的假绿。安全过滤器一律在 `WebConfig` 里用 `FilterRegistrationBean` 注册。
- **关键坑 2**：Servlet url pattern 不支持中段通配（`/internal/payments/*/channel-callback` 会被当精确匹配，永不命中）。注册用前缀 `/internal/payments/*`，具体路径在过滤器内用 `AntPathMatcher` 判定。
- **关键坑 3**：过滤器读完原始 body 后必须换 `CachedBodyHttpServletRequest` 包装器，否则下游 `@RequestBody` 读到空流。
- 验签失败用 `@MockBean PaymentCallbackService` + `verify(..., never())` 直接观测「业务处理没被调用」，比靠支付状态间接推断更硬。
- `BusinessMetrics` 有两个抽象方法，**不是函数式接口**，不能写 lambda，要用 `NoopBusinessMetrics`。

## 009 收尾 / 出站内部服务令牌闭环（T013）

- Roadmap 主线走完后，唯一真实代码缺口是 `009-risk-security` T013：ADR-0024 只做了**入站** `X-Service-Token` 守卫，调用方没地方带令牌 → `payment.security.internal-auth-enabled` 只能默认 false，一开就全线 403。
- 最简实现：`common-core` 新增 `InternalTokenRequestInterceptor`（Feign `RequestInterceptor`）+ `FeignInternalTokenAutoConfiguration`；**只对目标含 `/internal/` 段的请求发令牌**，对外 API/渠道 URL 一律不发（核心安全边界：不把内网共享密钥泄漏到平台外）。
- **关键坑 4：`${a:${b:}}` 嵌套默认值在空串场景不生效**。YAML 里 `service-token: ${PAYMENT_INTERNAL_TOKEN:}` 在 env 缺失时解析为**空字符串**而非「未定义」，Spring 对空串视作已配置 → 不会回退到嵌套默认值 → 集成测试直接 503。改为在 Java 侧 `firstNonBlank(serviceToken, platformToken)` 显式判空。
- **关键坑 5：Feign 目标路径要同时看 `url()` 和 `path()`**。服务名形态（`@FeignClient(name=...)`）在拦截器阶段还没解析出绝对 URL，路径留在 `uriTemplate`；显式 `url=...` 形态可能已拼好。两者取或。（feign-core 13.6.1：`path()` = target + uriTemplate，`url()` = path + query + fragment；`new RequestTemplate().uri(x)` 传绝对路径会抛异常，测试要用相对路径。）
- 自动配置沿用 `FeignTraceAutoConfiguration` 的**类级** `@ConditionalOnClass(feign.RequestInterceptor.class)` 门控，无 OpenFeign 的服务（merchant/catalog/entitlement）整类跳过。
- 顺带补了鉴权失败埋点（ADR-0037）：`payment.internal_auth_rejected` 带 `reason=unconfigured|missing_token|token_mismatch`。没有它，开关打开后出问题时无法区分「配置漂移全线 503」与「真实越权 403」。
- ADR-0034~0037 合并在 `docs/adr/0011-internal-token-decisions.md`（四五个 ADR 一个文档）；`docs/adr/README.md` 索引补到 0011；runbook 补 `PLATFORM_INTERNAL_TOKEN` 与「开启内部鉴权的正确顺序」（先开调用方出站 → 再开 payment 入站，反了会全站 403）。
- 实测：`mvn -o clean verify -fae` 全量 BUILD SUCCESS（14 模块 + root）。
