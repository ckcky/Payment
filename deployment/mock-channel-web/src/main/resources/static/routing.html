Feature 028 · ADR-0072 / ADR-0073

渠道两层结构与路由

payment 层负责编排支付单，channelAttempt 层负责与渠道交互并独占 channel_orders 的写入。 路由只产出渠道码字符串；反向路径（退款 / 重试 / 查询）一律按尝试行记录的渠道码解析，绝不重新选路。
观测口径：渠道归属一律读 channel_orders.channel_code 列，不解析渠道引用的字符串形态。

来自 GET /internal/channels。可用性是静态配置桩，不做真实探测（L1）。

③ 演示开关（仅 demo profile）
POST /internal/channels/{code}/status —— 覆盖配置的可用性，用于手工制造 DEGRADED / DOWN 场景。 只在内存生效，重启即回到配置值，不落库、不泄漏成持久状态。
提示：把 ALIPAY 置 DOWN 后回到 ②，「会选谁」会立刻变 WECHAT，「排除理由」会显示 unavailable (status=DOWN)。
④ 六个可演示场景
全部断言读 channel_orders.channel_code 列。命令行等价物：bash demo/scenario-routing.sh。

S1 · 只表达支付意图

建支付单时不传 channelCode，由平台按 priority 选路（US2 主路径）。
输入 {"items":[…]} 不含 channelCode → 期望 attempt(channel_code) = ALIPAY（enabled 且 priority 最小）

S2 · 显式指定优先

Router 对显式意图零干预，即使该渠道 enabled=false 也不拦截（L3）。
输入 channelCode=WECHAT → 期望 attempt(channel_code) = WECHAT

S3 · 自动避开停用渠道

DOWN 被排除出候选集；不指定渠道时会自动落到次优渠道。
输入 ALIPAY=DOWN + 不传渠道 → 期望 attempt(channel_code) = WECHAT

S4 · 明确拒绝，不偷改

显式指定的渠道 DOWN 时明确拒绝，不悄悄改选别的渠道——不篡改调用方意图。
输入 ALIPAY=DOWN + channelCode=ALIPAY → 期望 409 CHANNEL_UNAVAILABLE，且不落 payment_attempt（无部分写入）

S5 · 两渠道是各自独立的实现实例

三个 Adapter 是不同 Bean，各自声明自己的 channelCode；路由按身份寻址而非 if-else 分发。
分别显式 ALIPAY / WECHAT 各建一笔 → 期望两笔各自 attempt(channel_code) 落在各自渠道

S6 · 退款回原渠道（INV-6）

退款渠道取自被退支付单已记录的渠道码，禁止重新路由。资金安全红线：退款换渠道＝钱退错地方。
对 S2 的 WECHAT 支付发起退款 → 期望退款 attempt（attempt_type=REFUND）的 channel_code = WECHAT，不因 ALIPAY 优先级更高而改道
不做（Out of Scope）：不拆微服务／不拆事务边界；不做渠道失败自动 failover（与 INV-2 互斥）； 不做智能路由与权重分流；不接入真实渠道 SDK（三个 Adapter 在协议层仍是同一 mock 语义，L5）。
本页经同源代理 /proxy/payment/** 访问只读端点（ADR-0048），不为演示改动任何服务契约。
